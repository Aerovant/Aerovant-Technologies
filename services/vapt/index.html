We follow the path an attacker would.

From the internet, through your application and its APIs, into your network, toward the data. Each test covers one stretch of that path.

  1. Internet
  2. Web Application VAPTAn injection flaw or broken access control.
  3. API Security TestingAn endpoint returning another user’s data.
  4. Network Security TestingAn exposed admin port.
  5. Your data

The problem

A scanner tells you what might be wrong. It does not tell you what someone could do with it.

Vulnerability assessment

Finds and lists the weaknesses across what is in scope. Wide coverage. Answers “what is wrong here?”

Penetration testing

Tries to use those weaknesses, as an attacker would, to show what they lead to. Answers “does it matter?”

You need both. The first without the second gives you a long list and no priorities. The second without the first gives you one path and no coverage.

How a test runs.

  1. 1

    Scope.

    Targets, limits and testing windows, agreed with you before anything is touched.

  2. 2

    Test.

    Assessment first, then exploitation of what the assessment turns up.

  3. 3

    Report.

    Findings ranked by risk, each with evidence and what to change.

  4. 4

    Review.

    We go through the findings with the engineers who will fix them.

What you have at the end.

  • Proof of which weaknesses can be exploited, and which cannot.
  • Findings ranked by risk, with evidence.
  • Fix guidance written for the people doing the fixing.

Questions we get asked.

Will testing disrupt our production systems?

Targets, limits and testing windows are agreed with you before any testing starts. Nothing outside that scope is touched.

Can we test only the API, or only the web application?

Yes. The three tests can be taken separately. If you are not sure which matters most, tell us what you run and we will recommend one.

What do we receive?

A report of findings ranked by risk. Each one has the evidence for it and guidance on the fix.
